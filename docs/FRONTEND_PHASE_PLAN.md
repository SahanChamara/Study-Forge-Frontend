# StudyForge Frontend Development Plan

## Phase 0 — Product & UX Foundation
Define personas, information architecture, navigation, screen inventory, user flows, design tokens, component rules, data shapes, and API contract assumptions. No backend implementation.

## Phase 1 — Shell, Design System & Authentication UX
Build responsive app shell, navigation, reusable UI primitives, login/register/forgot-password screens, protected-route UX, skeletons, empty states, error states, and mock auth session.

## Phase 2 — Dashboard & Learning Paths
Build dashboard, path cards/list, create/edit path flows, path overview, module hierarchy, progress visualizations, and Linux sample path in mock data.

## Phase 3 — Topic Learning Workspace
Build module/topic navigation, topic objectives, resources, mastery control, status lifecycle, previous/next navigation, breadcrumbs, and distraction-light study layout.

## Phase 4 — Smart Notes & Practice
Build Markdown note editor/preview, note autosave UX, practice tasks/labs, evidence/result fields, recall questions, and completion/mastery workflows.

## Phase 5 — Review, Search & Analytics
Build global search UX, review queue, weak-topic views, progress analytics, activity history, filters, and mobile refinements.

## Phase 6 — Backend Integration & Hardening
Switch service provider from mock adapter to remote API adapter, connect Firebase web auth if required, handle token refresh and API errors, validate contract parity, run accessibility/performance/security checks, and prepare deployment.

Every phase requires explicit approval before the next phase.
